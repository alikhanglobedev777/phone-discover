# Patch 01 — Safe development foundation

This patch applies **after** `remove-phone-discover-malware.patch` to your existing Git clone.
It does not implement agentic search, phone ingestion, Pakistan price data, or Three.js.

## Windows PowerShell quick start

1. Review the patch and ensure your worktree is clean before applying.
2. Run `./scripts/init-dev-env.ps1` **once** from the project root. This creates private
   `.env` (Docker) and `backend/.env.local` (native Python) with random local credentials.
   Existing files are never overwritten. No Gemini key is needed for this patch.
3. To use native Django + Docker databases:
   - Install Python 3.12+, Docker Desktop, Node.js 22+.
   - Run `./scripts/setup-backend-native.ps1` (creates Python virtualenv, starts PostgreSQL
     and Redis, installs Python requirements, runs checks and migrations).
   - Run `./scripts/run-backend-native.ps1` in a separate terminal.
   - Inside `frontend/`, run `npm ci` then `npm run dev`.
4. Or to use only Docker: run `docker compose up --build -d`; view `http://localhost:5173`.
   Check `http://localhost:8000/api/health/` for `{"status":"ok"}`.
5. Run `./scripts/verify-foundation.ps1` for source checks and installed-tool checks.

For Django tests with a running PostgreSQL server:

```powershell
cd backend
./.venv/Scripts/python.exe manage.py test config catalog recommendations
```

A local Postgres password generated by this patch is stored in untracked environment files.
If a Postgres Docker volume already exists, its password may not match new credentials.
**Do not delete existing volumes to fix that**: recover/use the actual password or migrate
intentionally after backing up your data.

`backend/.env.local` and root `.env` are separate so native Python connects to
`127.0.0.1`, whereas the Compose backend connects to Docker's `db` hostname.
If you edit database credentials later, keep the two environment files consistent.

## Security limitations

This is a **local development** configuration, not a production deployment design.
It enables Django debug mode and exposes admin and APIs on localhost; keep the machine
trusted and do not publish local services to the internet. Admin and API authorization,
rate limiting, production transport/security configuration, backups, dependency audits,
updated phone models, and all agentic AI flows are later deliverables.

Run security and dependency reviews before installing packages or executing the project.
Changing tracked files does not remove malicious content from Git history or clean an
infected workstation. If the original payload ran, investigate that separately.

Gemini configuration belongs in the **untracked** `backend/.env.local` for native Django
or root `.env` for Compose, with `AI_PROVIDER=gemini`. Do not share API keys in chat or
commit them to Git. The AI provider still only explains local recommendations in Patch 01.
